# 知行项目功能分析与拓展路线

分析日期：2026-10-21

## 一、项目定位

“知行 · Knowledge in Motion”是一个面向科研学习与科学教育的关系型知识工作台。

它与普通笔记软件的主要区别是：不仅保存论文、代码、数据集、概念和实验记录，还显式保存它们之间的关系、证据与阅读路径，使科研理解过程可以追溯、探索和复用。

项目当前以具身智能和宇树开源模型为案例，但整体数据结构和交互框架可以扩展到其他科学领域。

核心使用闭环：

```text
论文／代码／数据集／概念
        ↓
建立知识对象和结构化关系
        ↓
通过图谱、画布和关系导航探索
        ↓
记录学习过程与实验结果
        ↓
形成可追溯、可复用的研究路径
```

## 二、主要功能

### 1. 科研知识库

系统支持以下九类知识对象：

- 概念（concept）
- 资料或论文（resource）
- 代码仓库（repository）
- 模型（model）
- 数据集（dataset）
- Benchmark（benchmark）
- 实验（experiment）
- 研究问题（question）
- 学习任务（task）

每个对象可以保存：

- 标题、摘要和 Markdown 正文
- 数学公式和代码块
- 标签和来源地址
- 阅读状态与掌握状态
- 类型相关的结构化元数据
- 本地附件
- 历史修订版本

编辑功能包括约 1.1 秒防抖自动保存、IndexedDB 本地草稿、保存失败保护、草稿下载以及多标签页版本冲突检测。

### 2. 带证据的知识关系

系统支持八种关系：

- `depends_on`：依赖前置概念或基础
- `implements`：实现某篇论文或方法
- `uses`：使用模型、数据或技术
- `evaluates`：评测某个对象
- `supports`：支持某个观点或结论
- `questions`：质疑或提出研究问题
- `compares_with`：横向比较
- `related_to`：一般关联

关系本身可以保存说明、证据对象、来源链接、页码或章节定位，以及用户对证据的解释。因此，这套关系不只是视觉连线，而是带来源的科研论证结构。

### 3. 全局知识图谱

系统使用 Cytoscape 展示知识网络，支持：

- 浏览全局知识图谱
- 按知识对象类型筛选
- 搜索和选择中心节点
- 展开一至三层关联
- 点击节点查看或修改知识对象
- 点击连线编辑关系和证据
- 在节点列表、关系列表和图谱视图之间切换

### 4. 沿关系阅读

知识详情页提供“沿关系阅读”功能：

- 显示当前阅读位置
- 区分前置知识、后续内容、使用关系和比较关系
- 按关系类型和方向筛选邻居
- 让局部图谱跟随当前笔记变化
- 标记访问过的节点和走过的连接
- 在当前浏览器标签页保留最近 40 次访问
- 从阅读路径返回之前的知识节点

这是当前项目最有辨识度的功能之一。它可以减少读者在论文、代码和概念之间切换时丢失上下文的问题。

### 5. 自由研究画布

系统使用 React Flow 提供自由画布，支持：

- 将知识对象拖入画布
- 创建自由文本卡片
- 移动、缩放和组合卡片
- 创建、修改和删除连线
- 撤销和重做
- 保存视口与布局
- 在不同画布中多次引用同一知识对象
- 将局部画布连线提升为正式知识关系

设计上区分了“局部思考连线”和“正式知识关系”：画布中的临时连接不会自动进入全局知识图谱，从而避免头脑风暴内容污染正式知识网络。

### 6. 学习轨迹

学习轨迹可以记录：

- 本次学习目标
- 实际活动
- 理解发生的变化
- 当前阻塞
- 下一步行动
- 相关知识对象
- 可选学习时长

这些记录与实验事件一起展示在时间线上，帮助用户回顾研究思路如何变化。

### 7. 实验与复现记录

实验模块能够保存：

- 实验主题和假设
- 运行状态
- 启动命令
- Git commit
- 模型权重版本
- 数据集版本
- 配置、运行环境和随机种子
- 评估指标
- 结果与失败原因
- 外部实验产物路径

当前模块主要负责实验记录与追溯，不会实际调度或执行模型实验。

### 8. 数据保护与恢复

项目实现了：

- 软删除和回收站
- 删除后的快速撤销
- 显式永久删除确认
- 知识对象和画布的版本历史
- 附件大小限制与 SHA256 校验
- ZIP 整库备份
- 导入前预检查
- ID 冲突检测
- 损坏或篡改附件检测
- 恢复失败时的事务回滚

## 三、技术架构

### 前端

- React 18
- Vite 5
- Tailwind CSS
- React Router
- Cytoscape.js
- React Flow
- React Markdown、KaTeX
- IndexedDB 和 sessionStorage

主要页面包括工作台、知识与资料、知识图谱、自由画布、学习轨迹、实验与复现、回收站以及环境与备份。

### 后端

- Python
- FastAPI
- Pydantic
- psycopg2
- 显式 SQL 和数据库事务

后端提供知识对象、关系、图谱、画布、学习日志、实验运行、附件、回收站、导入和导出接口。

### 数据库

- PostgreSQL
- 版本化 SQL 迁移
- UUID 主键
- JSONB 类型扩展字段
- 乐观锁版本号
- 关系、证据、修订和软删除结构

### 本地数据边界

- PostgreSQL：知识、关系、画布、日志和实验记录
- `storage/`：附件、备份和运行日志
- IndexedDB：尚未成功提交的浏览器草稿
- sessionStorage：当前标签页的阅读路径

## 四、当前案例与完成度

仓库包含一套宇树开源模型研究案例：

- 60 个知识对象
- 91 条知识关系
- 模型、论文、源码、数据集和概念笔记
- 4090 本地复现路线与资源预算
- 待运行实验和完成条件

该案例已经完成资料核对与知识结构准备，但尚未完成实际 GPU 模型复现。因此，现有内容可以作为研究组织与导航案例，不能作为模型已经成功复现或教学效果已经得到验证的证据。

仓库还包含后端测试和 Playwright 浏览器测试，覆盖版本冲突、关系证据、画布持久化、删除恢复、备份恢复、附件完整性、阅读路径和基础响应式页面。

## 五、当前边界

当前版本是一个本地单人工作台，主要限制包括：

- 没有账号、登录和权限系统
- 没有多人实时编辑或数据同步
- 不支持多个数据库副本的自动合并
- 没有语义搜索和向量检索
- 没有 LLM 问答或自动知识抽取
- 实验模块不会实际启动或监控实验
- 宇树案例尚未执行 GPU 复现
- 跨学科适用性和教育效果尚未验证
- 后端功能集中在单个 `backend/app.py`，继续扩展前适合拆分路由、服务和数据访问层

## 六、推荐拓展方向

### 第一优先级：增强黑客松差异化

#### 1. AI 辅助资料导入

允许用户输入 PDF、arXiv、DOI 或 GitHub 地址，自动提取：

- 标题、作者、摘要与来源
- 候选概念和关键词
- 候选知识对象
- 候选关系
- 对应证据片段和页码

自动生成的内容应先作为候选项，由用户确认后再进入正式知识图谱。这样可以提高效率，同时维持来源可信度。

#### 2. 基于关系和证据的科研问答

增加知识问答功能，但不要只返回普通的自然语言答案。每个回答应该同时展示：

- 使用了哪些知识对象
- 经过了哪条关系路径
- 对应来源与证据位置
- 哪些结论缺少证据
- 哪些对象存在冲突或不同观点

例如，用户询问“UnifoLM-VLA-0 依赖哪些基础模型”，系统可以回答问题，同时在图谱中高亮推理路径。

#### 3. 可量化的教学评估

设计一个小型对照实验，比较普通文件夹或线性笔记与关系型知识工作台，测量：

- 找到前置知识所需时间
- 来源追溯正确率
- 阅读路径完成率
- 对知识关系的理解程度
- 用户对导航清晰度的评分

这可以让比赛展示从“功能演示”提升为“有初步验证的解决方案”。

### 第二优先级：提高实际使用价值

#### 4. 混合检索

结合以下三种信息：

- 标题和正文关键词
- 向量语义相似度
- 图谱关系距离

搜索结果不仅返回匹配笔记，还可以返回相关模型、数据集、实验失败记录和研究问题。

#### 5. 智能关系建议

根据文本相似度、引用信息和现有图结构推荐可能遗漏的连接，并说明推荐原因。所有推荐关系仍应由用户确认。

#### 6. 自动化实验追踪

逐步增加：

- 从工作台启动本地实验
- 记录进程状态和运行日志
- 自动收集 Git commit、环境和指标
- 将失败日志连接到相关概念和任务
- 对接 MLflow、Weights & Biases 或 DVC

#### 7. 跨领域知识案例

在具身智能之外增加一个规模较小但领域明显不同的案例，用于验证数据结构和阅读导航是否真正具有通用性。

### 第三优先级：协作与产品化

#### 8. 多人协作

增加：

- 账号和团队空间
- 角色与访问权限
- 评论和审核流程
- 修改历史与责任人
- 关系变更审批
- 数据同步和冲突处理

建议先实现异步协作，再评估实时共同编辑。

#### 9. 自适应学习能力

可以根据知识图谱生成：

- 带前置条件的学习路线
- 每个节点的自测问题
- 间隔复习计划
- “可以解释、可以实现、可以复现、可以分析”的验收任务

系统不应仅根据浏览次数自动判断用户已经掌握知识。

#### 10. 外部工具集成

建议优先支持：

- Zotero 和 BibTeX
- arXiv 和 DOI
- GitHub 仓库
- Obsidian Markdown
- Notion 导出
- CSV、JSON 或通用图谱格式

## 七、建议的黑客松版本范围

如果开发时间有限，建议比赛版本集中完成三项：

1. PDF 或 arXiv 自动提取候选知识对象、关系和证据。
2. 能展示来源、证据和图谱路径的科研问答。
3. 一个带评估指标的跨领域学习演示。

这些能力都可以建立在当前数据结构和界面之上，不需要推翻现有项目。

## 八、总结

项目最清晰的价值主张可以概括为：

> 知行把分散的论文、代码、概念和实验组织成带证据、可导航、可回看的科学推理路径。

项目当前已经形成知识录入、关系建模、图谱浏览、画布整理、关系阅读、学习记录、实验追踪和备份恢复的完整闭环。下一阶段最值得投入的方向，是让 AI 帮助用户建立和查询有证据的知识网络，并通过实际学习任务验证它是否能够提高科研理解和科学沟通效率。
