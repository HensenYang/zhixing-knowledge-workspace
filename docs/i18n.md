# Interface localization / 界面国际化

The interface supports `zh` (default) and `en`. The header switch persists `workspace:language` in localStorage and synchronizes other open tabs. It also updates the document language, page title, and date formatting. Storage failures fall back to an in-memory preference.

界面默认使用中文，可在顶栏切换为英文。语言偏好保存在浏览器，并同步至其他已打开的标签页。切换不会重新挂载编辑器、重置表单或修改知识库内容。

## Adding interface text

Add the same key to `frontend_Web/src/i18n/zh.json` and `en.json`:

```json
// zh.json
"lesson.completed": "已完成 {count} 个学习步骤"
// en.json
"lesson.completed": "Completed {count} learning steps"
```

Render it with a subscription:

```jsx
import { t, useLanguage } from '../i18n';

function LessonProgress({ count }) {
  useLanguage();
  return <p>{t('lesson.completed', { count })}</p>;
}
```

Existing messages mostly use their Chinese source text as keys. New messages may use descriptive keys, as above. Use placeholders for complete sentences, not translated fragments. Dates use `dateLocale()`.

For module-level label maps, use `msg('lesson.completed')` to retain a key and call `t(key, values)` when rendering. For statuses stored in state, store a key with `msg()` and translate on render. Use `translateMessage()` for server errors; existing Chinese server messages and parameterized error templates have English equivalents in the catalogs. New backend messages shown to users must be added to both catalogs.

Do not translate user-authored content or pass it through `t()`. The interface switch does not translate existing research notes, sample records already in a database, or model responses. Initial sample records are created in the selected language and then treated as editable content.

新增或修改界面文案时，必须同时更新两份词典；也要覆盖提示、校验信息及无障碍标签。用户内容、数据库枚举值和接口标识不得随界面语言改变。

## Checks

From `frontend_Web`:

```powershell
npm run check:i18n
npm run test:i18n
npm run build
npx playwright test tests/i18n-language.spec.js tests/reading-navigation.spec.js tests/llm-settings.spec.js
```

The build includes the catalog check. It checks matching keys and placeholders, missing translations, unmarked Chinese strings, and hard-coded visible JSX text and dialog labels. Technical names such as PostgreSQL, API Key, and KB are allowed unchanged. Tests use mocked APIs and do not require model credentials or a database.
